# Сопоставление учительских дампов с исходными QA-текстами

Дата проверки: 11 ноября 2026 года.

Восстановлены ссылки из трёх локальных учительских дампов на исходные тексты
HotpotQA и MuSiQue. Проверка относится к происхождению примеров и индексам
контекстов, а не к смысловой правильности извлечённых фактов.

## Источники

- **HotpotQA, distractor validation:** 7 405 QA-примеров. Исходный сервер
  `curtis.ml.cmu.edu`, указанный на [сайте проекта](https://hotpotqa.github.io/),
  не разрешался через DNS при загрузке. Использован Parquet из
  [hotpotqa/hotpot_qa на Hugging Face](https://huggingface.co/datasets/hotpotqa/hotpot_qa).
  Это представление данных с полем `id` вместо исходного `_id` и словарём
  `context` с массивами `title` и `sentences`. Лицензия данных — CC BY-SA 4.0.
- **MuSiQue v1.0:** официальный архив по ссылке из
  [download_data.sh](https://github.com/stonybrooknlp/musique/blob/main/download_data.sh).
  Для сопоставления использованы `musique_ans_v1.0_dev.jsonl` — 2 417 записей
  и `musique_full_v1.0_train.jsonl` — 39 876 записей. Лицензия данных — CC BY 4.0.

URL, размеры файлов и SHA-256 сохранены в [машиночитаемом отчёте](source_matching.json).
Контрольные суммы также проверяются при повторном запуске загрузки. Сырые данные,
учительские дампы и восстановленные тексты исключены из публикации через `.gitignore`.
Настройка ignore сама по себе не удаляет ранее отслеживаемые файлы.

## Метод сопоставления

1. Для HotpotQA ключ верхнего уровня дампа сопоставляется с `id`, вложенный числовой
   ключ — с позицией контекста. Текст восстанавливается как
   `" ".join(sentences).strip()`, как в прежнем скрипте подготовки данных Wikontic.
2. Для первого MuSiQue-дампа используются точный `id` и поле `paragraphs[].idx`,
   текст берётся из `paragraph_text` без нормализации.
3. В третьем дампе ID имеет вид `<source_id>_Answerable` или
   `<source_id>_Unanswerable`. Он сопоставляется с парой `(id, answerable)`
   из MuSiQue-Full train. Простое удаление суффикса недостаточно: в Full один
   базовый ID встречается у ответимого и неответимого вариантов с разными контекстами.
4. Проверяются отсутствие неоднозначных ключей, наличие всех запрошенных контекстов
   и непустой исходный текст. Для каждого сопоставленного контекста сохраняются
   источник, ID, заголовок, текст и его SHA-256.

Неответимость QA-вопроса не означает, что в его контекстах нет фактов для извлечения.
В третьем дампе найден 831 ответимый и 814 неответимых примеров.

|---|---:|---:|---:|

| `kg_dump_musique_gpt4_1_onto_triplets.json` | 200 / 200 | 3 996 / 3 996 | 3 201 |
| `kg_dump_triplets_musique_train_split_occ_openai_gpt_oss_120b_onto.json` | 1 645 / 1 645 | 32 844 / 32 844 | 20 726 |

Пропущенных ID, отсутствующих ссылок на контексты и пустых сопоставленных текстов
не обнаружено. Всего восстановлено 38 839 контекстных записей. Это число включает
повторы; оно не равно количеству уникальных документов.

### Пересечения текстов между дампами

| Пара источников | Уникальных общих текстов |
|---|---:|
| HotpotQA validation и MuSiQue-Ans dev | 0 |
| HotpotQA validation и MuSiQue-Full train | 0 |
| MuSiQue-Ans dev и MuSiQue-Full train | 514 |

Пересечения рассчитаны по точному SHA-256 текста после описанного восстановления,
без приведения регистра, удаления пробелов или поиска близких формулировок.
Нулевое пересечение не исключает одинаковые статьи с другим форматированием.

## Выводы для дальнейшей работы

- Данных достаточно, чтобы начать текстовый EDA и аудит учительских фактов:
  для каждой записи найден кандидат исходного контекста.
- Два первых дампа относятся к официальным **dev/validation**, а не train.
  Если их использовать при обучении, эти примеры нельзя оставлять в независимой
  оценке, даже если исходный датасет называет их dev.
- Между MuSiQue train и dev уже найдено **514 одинаковых текстов** в рассматриваемых
  подвыборках. Для будущих splits необходима группировка контекстов поверх QA-ID.
- Восстановление по ID и индексу не доказывает, что учитель видел побайтно тот же
  текст: исходные дампы не содержат текстовых хешей или полного входа учителя.
  Необходим ручной аудит связей и дополнительная проверка происхождения.
- В дампах нет evidence. Восстановленный полный контекст не является автоматически
  подтверждающим фрагментом для каждого триплета; evidence предстоит разметить
  или получить отдельным проверяемым методом.
- CaRB здесь не использовался и не загружался. Независимая benchmark-оценка
  остаётся отдельным этапом.

## Воспроизведение

Из корня проекта с активированным Python 3.12 окружением:

```bash
python -m pip install -r requirements-data.txt
python scripts/download_qa_sources.py
python scripts/match_teacher_sources.py
```

Ожидаются три локальных учительских файла в `data/teacher/` с именами из таблицы.
Получение дампов с HF описано в [README проекта](../README.md#данные-для-дз-2);
закреплена ревизия `48caaeef5a103a775392a4b7fa14c90fa94e259f`
[публичного Dataset](https://huggingface.co/datasets/bl4ckse4m/wikontic-lite-teacher-data/tree/48caaeef5a103a775392a4b7fa14c90fa94e259f).
14.11.2026 все три дампа скачаны без авторизации потоковой проверкой;
их SHA-256 совпали с приведёнными в `source_matching.json`. На HF указана
CC BY-SA 4.0 и присутствует текст лицензии; лицензии исходных QA-наборов сохраняются.
Загрузчик сохраняет источники в `data/raw/` и использует существующие файлы после
проверки контрольных сумм. Сопоставление выполняется локально, без API моделей.

Выходы:

- `data/raw/source_manifest.json` — сведения о скачанных файлах;
- `data/processed/matched_contexts.jsonl` — восстановленные тексты с provenance;
- `reports/source_matching.json` — агрегированные результаты, контрольные суммы
  и пересечения, без текстов и учительских ответов.

Это начальная проверка источников, не полный EDA: анализ длин, качества разметки,
семантических ошибок и близких дубликатов выполняется следующим шагом.
